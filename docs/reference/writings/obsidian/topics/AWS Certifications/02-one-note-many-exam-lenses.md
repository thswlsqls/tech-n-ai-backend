# 02. 폴더로 시험을 쪼개지 마라 — 노트 하나에 시험별 관점 얹기

> 1차 소스: 마렉(Stéphane Maarek) 강의 슬라이드 3덱(로컬 `contents/AWS/`, 저작권·개인 사용 한정 — 구조만 참고, 본문 전재 금지)

## 한줄 요약(Hook)

> SAA·DVA·CloudOps 폴더를 따로 만들어 S3 노트를 세 번 쓰면 관리가 무너집니다. 세 시험은 같은 서비스를 다른 각도로 볼 뿐이라, 서비스 노트는 하나만 두고 시험별 관점을 태그·속성으로 얹습니다. 마렉 강의도 공통 영상을 재사용해 이 구조로 짜여 있습니다.

## 핵심 질문

- 세 시험이 공유하는 서비스(EC2·S3·IAM·VPC…)를 어떻게 한 번만 정리하나?
- 시험별 관점은 폴더 대신 무엇으로 구분하나?
- 마렉 강의의 구성이 이 방식을 어떻게 뒷받침하나?

## 다루는 관점

- ✅ 개념 이해(Why) — 폴더 중복의 함정, 공유 지식이라는 관점
- ✅ 실전 기본기 — 태그(`#saa`), 속성으로 "이 노트가 어느 시험·도메인에 걸리나" 표시
- ✅ 자격증 공부 적용 — 한 서비스 노트로 세 시험을 동시에 대비

## 근거

- [1차] 마렉 SAA 도입 슬라이드 — "shared knowledge from Cloud Practitioner, Developer and SysOps course"
- [1차] 마렉 CloudOps 도입 슬라이드 — 강의를 `[CCP]`/`[SAA]`/`[DVA]` 재사용 영상 + CloudOps 특화 영상으로 구성
- [1차] 세 덱의 목차 — IAM·EC2·S3·RDS·Route 53·VPC·CloudFront·Lambda 등 공통 섹션 + 시험별 특화 섹션
- [공식] 세 시험의 도메인이 보안·배포·모니터링에서 겹친다는 점(03에서 비중으로 확인)
- [공식] 내부 링크, 태그, 속성

## 타깃 독자 & 난이도

- ★★☆☆☆ (사전지식: 01의 Vault·링크)

## 예상 분량

## 글 아웃라인

1. **들어가며 — 시험별 폴더의 함정**
   - `SAA/S3.md`, `DVA/S3.md`, `CloudOps/S3.md`로 같은 내용을 세 번 쓰면 무엇이 깨지나
2. **세 시험은 같은 서비스를 다른 각도로 본다**
   - SAA는 설계, DVA는 개발, CloudOps는 운영 — 대상 서비스는 크게 겹친다(공식 도메인 겹침은 03)
3. **마렉 강의도 공유 모듈로 짜여 있다**
   - 강의가 공통 영상을 재사용하고 시험별 영상만 얹는 구조라는 사실(목차·도입 수준)
   - 저작권: 강의 슬라이드 내용은 개인 Vault에서만, 공개 글에 옮기지 않는다
4. **서비스 노트 하나 + 시험별 관점 태그**
   - `[[S3]]` 한 노트 안에 "설계 관점/개발 관점/운영 관점"을 두고 `#saa`·`#dva`·`#cloudops`로 표시
5. **속성으로 노트가 걸리는 시험·도메인 표시**
   - YAML 프런트매터에 `exams: [saa, dva, cloudops]` 같은 속성으로 분류(상세 타입은 03)
6. **마무리 — 관점을 얹었으니, 공식 도메인으로 구조화한다**
   - 다음 편 예고: 공식 도메인 비중으로 노트와 진도를 잡는 법

## 작성 메모

- 마렉 슬라이드는 **구조 사실(목차 수준)만** 쓴다. 슬라이드 본문·문구·캡처를 글에 옮기지 않는다(저작권 고지 그대로).
- "한 노트, 여러 관점"을 마렉 구조로 정당화하되, "마렉 강의가 최고"라는 식의 평가는 넣지 않는다(의견과 사실 분리).
- 태그·속성의 깊은 사용법은 03으로 미룬다. 여기서는 "폴더 대신 관점을 얹는다"는 원리까지만.
