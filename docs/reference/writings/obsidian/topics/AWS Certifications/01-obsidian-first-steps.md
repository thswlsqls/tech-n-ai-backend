# 01. Obsidian 첫걸음 — Vault·평문 마크다운·링크라는 멘탈 모델

## 한줄 요약(Hook)

> 폴더 트리에 익숙한 개발자가 Obsidian에서 처음 바꿔야 하는 건 도구 사용법이 아니라 사고방식입니다. 노트는 내 디스크의 평문 마크다운 파일이고, 정리는 폴더가 아니라 노트 사이의 링크로 합니다. 자격증 공부를 시작하기 전에, 이 멘탈 모델부터 세웁니다.

## 핵심 질문

- Obsidian은 노트를 어디에, 어떤 형식으로 저장하나? (Vault와 평문 마크다운)
- 폴더(트리)와 링크(그래프)는 지식 정리에서 무엇이 다른가?
- 세 자격증 공부를 시작할 Vault를 어떻게 잡아야 하나?

## 다루는 관점

- ✅ 개념 이해(Why) — Vault가 로컬 폴더라는 점, 평문 마크다운이라 데이터를 내가 소유한다는 점
- ✅ 실전 기본기 — Vault 만들기, 첫 노트 쓰기, `[[ ]]`로 첫 링크 걸기
- ✅ 자격증 공부 적용 — SAA-C03·DVA-C02·SOA-C03를 한 Vault에서 시작하는 첫 세팅

## 근거

- [공식] Vault 정의 — "a folder on your local file system where Obsidian stores your notes"
- [공식] 노트가 평문 마크다운(`.md`)으로 저장된다는 점, 데이터 소유·로컬 우선
- [공식] 내부 링크 `[[Note name]]`의 기본 문법

## 타깃 독자 & 난이도

- Obsidian을 처음 쓰는, 개발자 출신 데브옵스 엔지니어
- ★☆☆☆☆ (사전지식: 마크다운을 읽고 쓸 줄 아는 수준)

## 예상 분량

- 보통 (~3,500자)

## 글 아웃라인

1. **들어가며 — 개발자가 노트 앱에서 처음 헷갈리는 것**
   - 폴더로 모든 걸 분류하려다 막히는 지점
2. **Vault = 내 디스크의 폴더**
   - 노트는 평문 마크다운 파일, 클라우드가 아니라 로컬에 저장됨 → 데이터를 내가 소유
   - 평문이라 git으로도 버전 관리가 된다(단, git 연동은 Obsidian 기본 기능이 아니라 별도 설정)
3. **폴더 트리 vs 링크 그래프**
   - 폴더: 한 노트는 한 곳에만 들어간다
   - 링크: 한 노트가 여러 맥락에 동시에 속한다 — AWS 서비스처럼 여러 시험에 걸치는 지식에 맞다
4. **첫 링크 — `[[EC2]]` 한 줄로 노트를 잇는다**
   - 위키링크 문법, 아직 없는 노트로도 링크를 걸어 둘 수 있다
5. **자격증 공부 Vault 첫 세팅 — 폴더는 최소로**
   - 서비스 노트를 둘 곳 하나, 첨부를 둘 곳 하나 정도면 충분. 시험별 폴더는 만들지 않는다(이유는 02)
6. **마무리 — 문법보다 먼저 넘어야 할 건 "링크로 생각하기"**
   - 다음 편 예고: 세 시험이 공유하는 지식을 한 번만 정리하는 법

## 작성 메모

- "평문·로컬·소유"는 개발자 독자에게 잘 먹히는 진입점이다. 다만 Obsidian이 git을 내장한 것처럼 쓰지 말 것 — git 연동은 별도 플러그인·설정이다(과장 금지).
- "폴더를 쓰지 마라"는 극단으로 가지 말 것. 폴더는 최소로 두고 연결을 링크로 한다는 균형으로 적는다.
- 이 편은 개념 멘탈 모델까지만. 태그·속성·그래프의 상세는 뒤 단편으로 미룬다(한 편에 다 넣지 않는다).
