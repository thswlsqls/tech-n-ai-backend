# 05. 복습과 약점 점검 — 태그·그래프·커뮤니티 플러그인으로 시험 직전 굴리기

> 1차 소스: Obsidian 공식 문서(Tags·Graph view·Plugins)

## 한줄 요약(Hook)

> 자격증은 막판에 다 보는 게 아니라 약점만 모아 도는 게 효율적입니다. 함정을 태그로 모으고, 그래프 뷰로 연결이 빈약한 노트(덜 정리한 서비스)를 찾습니다. 암기·간격 반복은 커뮤니티 플러그인으로 확장할 수 있지만, 특정 플러그인의 동작은 그 플러그인 공식 문서로 직접 확인해야 합니다.

## 핵심 질문

- 시험 직전에 약점·함정만 어떻게 모아 보나?
- 그래프 뷰로 덜 정리한 영역을 어떻게 찾나?
- 암기·복습은 무엇으로 확장하나? (core plugin과 community plugin의 경계)

## 다루는 관점

- ✅ 개념 이해(Why) — 막판 복습은 "전부"가 아니라 "약점"
- ✅ 실전 기본기 — 태그 필터, 그래프 뷰(core plugin), core/community 플러그인 경계
- ✅ 자격증 공부 적용 — 시험 직전 한 주 루틴

## 근거

- [공식] Tags — `#` 태그와 `/`로 만드는 계층 태그(`#exam/trap`)로 함정 모으기
- [공식] Graph view — core plugin, 노드(노트)·링크 시각화, 연결이 적은 노드 식별
- [공식] core plugins vs community plugins — community plugins는 "features built by Obsidian users"로 워크플로를 더한다
- [확인 필요] 간격 반복(spaced repetition) 같은 특정 커뮤니티 플러그인의 기능·문법은 이번 조사 범위 밖. 글에 쓰려면 그 플러그인 공식 저장소·문서로 직접 확인

## 타깃 독자 & 난이도

- 노트·자료를 쌓아 둔, 시험을 앞둔 개발자 출신 데브옵스 엔지니어
- ★★★☆☆ (사전지식: 01~04)

## 예상 분량

- 보통 (~4,000자)

## 글 아웃라인

1. **들어가며 — 막판엔 다 보지 말고 약점만**
   - 2,500쪽 강의를 다시 정독할 수 없다, 약점을 추려 도는 전략
2. **함정 태그로 모으기**
   - 공부하며 틀린 지점을 `#exam/trap`(계층 태그)로 달아 두고, 검색·태그 패널로 한자리에 모은다
3. **그래프 뷰로 빈약한 영역 찾기**
   - 연결이 적은 노드 = 덜 정리한 서비스. 그래프로 공백을 눈으로 찾는다
4. **확장 — core plugin과 community plugin**
   - 그래프·태그·속성은 켜고 끄는 core, 암기·간격 반복 같은 건 community plugin으로 더한다
   - 특정 플러그인을 쓰려면 그 플러그인 공식 문서를 확인한다(이 글은 공식으로 확인된 기능까지만 단정)
5. **시험 직전 한 주 루틴**
   - 함정 태그 정주행 → 그래프 공백 메우기 → 도메인 진도표(03) 빈칸 점검
6. **마무리 — 시리즈를 닫으며**
   - 01의 멘탈 모델부터 05의 막판 점검까지, 한 Vault로 세 시험을 굴리는 그림

## 작성 메모

- 특정 플러그인 이름·기능을 사실처럼 단정하지 않는다. "커뮤니티 플러그인으로 이런 확장이 가능하고, 쓰려면 해당 플러그인 공식 문서를 확인하라"까지만.
- 그래프 뷰·태그는 공식 기능이라 단정해도 된다. "연결이 적은 노드 = 약점"은 학습 해석이므로, 단정 대신 "이렇게 활용할 수 있다"로 적는다.
- 마무리에서 시리즈 전체를 한 번 잇되, 앞 단편이 답한 "왜"를 되풀이하지 않는다(인과 사슬만 짧게).
