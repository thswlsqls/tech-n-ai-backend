# 04. 루프 엔지니어링 — Anthropic이 만든 말이 아니다

## 한줄 요약(Hook)

> Claude Fable 5 공식 발표문(2026-06-09)에는 "loop engineering"이라는 단어가 없다. 그런데 출시 전후로 이 말이 퍼졌다. 발표문을 직접 읽어 단어의 부재를 확인하고, 그 말이 실제로 어디서 왔는지(Anthropic 소속 개인의 발언과 외부 블로거의 명명) 경로를 추적하면, 형성 중인 용어를 다루는 법이 보인다.

## 핵심 질문

- Fable 5 공식 발표문이 실제로 말한 것은 무엇인가?
- "루프 엔지니어링"이라는 말은 누가 언제 했고, 누가 이름을 붙였나?
- 하네스와 루프는 어떻게 다른가?
- 컨텍스트 엔지니어링(02)은 공식 어휘가 됐다. 이 용어는 지금 생애주기의 어디에 있나?

## 다루는 관점

- ✅ 발전 배경(Why) — 장기 자율 모델의 등장과 "프롬프트하는 사람"의 위치 변화
- ✅ 핵심 기법 — 루프의 구성(일감 찾기 → 실행 → 검증 → 기록 → 반복)을 발언 인용 범위에서
- ✅ 용어의 출처 — 사실 교정: 공식 발표가 아니라 개인 발언 + 외부 명명

## 근거

- Anthropic, *Claude Fable 5 and Claude Mythos 5* (2026-06-09) — "Fable 5 and Mythos 5 can work autonomously for longer than any previous Claude models". 장기 자율 작업 능력을 강조. **이 발표문에 "loop engineering"이라는 표현은 등장하지 않음** (원문 직접 확인, 2026-06-13 기준)
- [미검증 · 근거 아님] Boris Cherny(Anthropic Claude Code 리드)의 X 발언 — "I don't prompt Claude anymore. I have loops running that prompt Claude... My job is to write loops." 원본 게시물은 직접 확인하지 못했고 2차 인용으로만 확인
- [미검증 · 근거 아님] Addy Osmani, *Loop Engineering* (개인 블로그, 2026-06-07) — 정의: "Loop engineering is replacing yourself as the person who prompts the agent. You design the system that does it instead." 위치: "one floor above the harness". Peter Steinberger의 비슷한 발언도 함께 인용

## 타깃 독자 & 난이도

- Claude Code 같은 AI 코딩 도구를 일상적으로 쓰지만, 쏟아지는 엔지니어링 용어의 계보를 정리하지 못한 백엔드 개발자
- ★★★☆☆ (사전지식: 01~03편. 특히 03의 하네스 개념)

## 예상 분량

- 김 (완성 글 기준 9,000자 안팎)

## 글 아웃라인

1. **들어가며 — 유행하는 말일수록 출처를 확인한다**
   - "Fable 출시와 함께 Anthropic이 발표한 개념"이라는 인상이 퍼졌지만, 사실 확인 결과는 다르다는 문제 제기
2. **공식 발표문이 실제로 말한 것**
   - Fable 5 발표문의 장기 자율성 인용. 그리고 그 문서에 loop engineering이라는 단어가 없다는 직접 확인 결과
3. **단어의 실제 경로 — 발언, 명명, 유행**
   - Cherny·Steinberger의 발언(미검증·2차 인용임을 밝힘) → 6월 7일 외부 블로거의 명명 → 6월 9일 Fable 5 출시 → 시기가 겹치며 함께 회자
4. **하네스 위의 층 — 무엇이 다른가**
   - 03의 하네스는 "모델 주변 시스템"이고, 루프는 그 시스템을 언제 시작하고 멈추고 다시 시킬지를 정하는 한 층 위. 일감 찾기 → 실행 → 검증 → 기록 → 반복이라는 구성
5. **용어의 생애주기 — 컨텍스트 엔지니어링과의 평행 비교**
   - 02의 사례: X 발언(2025-06) → 3개월 뒤 공식 문서 채택(2025-09). 루프 엔지니어링은 아직 발언·명명 단계이고 공식 채택은 없다는 현재 위치
6. **네 층의 사다리 — 시리즈 총정리**
   - 설계 대상의 이동: 문장(01) → 토큰 구성(02) → 모델 밖 시스템(03) → 시스템을 돌리는 시스템(04)
7. **마무리 — 형성 중인 용어를 다루는 법**
   - 단어가 공식화되기 전에 개념을 먼저 이해해 두면, 이름이 바뀌어도 흔들리지 않는다는 개인 인사이트로 닫는다

## 시리즈 인용 관계

시리즈의 **마무리** 편이다. 03이 열어 둔 "하네스를 돌리는 건 여전히 사람"이라는 질문에 답하고, 02의 "용어 생애주기" 관찰을 대조 사례로 재인용한다(컨텍스트 엔지니어링 = 공식화 완료, 루프 엔지니어링 = 형성 중). 6번 절의 네 층 사다리가 01~03의 결론을 한 문장씩만 빌려와 시리즈를 닫는다 — 각 편의 근거를 다시 펼치지 않는다.

## 작성 메모

- **절대 "Anthropic이 발표한 개념"이라고 쓰지 않는다.** 이 글의 차별점은 그 인상을 교정하는 데 있다. "Anthropic 소속 개인의 발언이고 공식 문서화는 안 됐다"가 정확한 서술이다.
- Cherny 발언은 원본 X 게시물을 직접 확인하지 못했다. "~라고 인용된다" 수준으로 쓰고, 단정하지 않는다.
- 미검증 출처(Osmani 글, X 발언)는 **본문에서 등급을 밝힌다.** "개인 블로그의 정의에 따르면" 같은 식으로, 공식 정의가 없다는 사실 자체를 드러낸다.
- 루프의 구성(일감 찾기~반복)은 미검증 출처의 정리이므로 "이렇게 설명된다" 톤을 유지한다. 확립된 방법론처럼 쓰면 이 글의 주제와 모순된다.
- 글 작성 시점에 Anthropic이 이 용어를 공식 채택했는지 **재확인**한다. 5번 절의 "아직 공식 채택 없음"은 2026-06-13 기준 사실이고, 바뀌면 글의 결론도 바뀐다.
