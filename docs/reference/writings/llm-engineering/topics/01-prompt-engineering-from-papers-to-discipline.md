# 01. 프롬프트 엔지니어링 — 문장 쓰기가 엔지니어링이 된 출발점

## 한줄 요약(Hook)

> 2020년 GPT-3 논문은 모델을 다시 학습시키지 않고 입력 텍스트만으로 과제를 시킬 수 있다는 걸 보여줬다. 그 순간부터 "입력 문장을 잘 쓰는 일"이 기술이 됐다. 4년 뒤 쏟아지는 컨텍스트·하네스·루프 엔지니어링이라는 말들은 전부 이 출발점에서 한 층씩 올라간 것이다.

## 핵심 질문

- 2020년 이전에는 왜 프롬프트 엔지니어링이라는 분야가 없었나? (fine-tuning이 기본이던 시절과 in-context learning의 차이)
- Chain-of-Thought 논문은 무엇을 증명했나 — 프롬프트가 성능을 어디까지 좌우하나?
- 공식 문서는 프롬프트 엔지니어링을 언제 쓰라고 권하고, 어떤 기법으로 정리하나?
- 한 턴짜리 프롬프트 최적화의 한계는 어디서 오나?

## 다루는 관점

- ✅ 발전 배경(Why) — fine-tuning에서 in-context learning으로의 전환
- ✅ 핵심 기법 — 공식 문서가 정리한 프롬프트 기법의 체계
- ✅ 용어의 출처 — 기법의 기원(논문)과 용어의 기원(불명)을 구분

## 근거

- Brown et al., *Language Models are Few-Shot Learners* (arXiv:2005.14165, 2020-05-28 제출) — gradient update나 fine-tuning 없이 "텍스트 상호작용만으로 과제와 소수의 예시를 지정"해 GPT-3을 쓸 수 있음을 보임
- Wei, Wang, Schuurmans et al., *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models* (arXiv:2201.11903, 2022-01 제출) — 중간 추론 단계를 예시로 주면 추론 성능이 크게 오름
- Anthropic Prompt engineering overview — 전제 조건(성공 기준 정의, 평가 방법, 초안 프롬프트), 프롬프트로 풀 문제와 아닌 문제(지연·비용은 모델 선택)의 구분, 기법 목록(명확한 지시·예시·XML 구조화·역할 부여·프롬프트 체이닝)

## 글 아웃라인

1. **들어가며 — 용어가 너무 빨리 늘어난다**
   - 프롬프트 → 컨텍스트 → 하네스 → 루프. 4개 용어가 6년 사이에 나온 배경을 시리즈로 추적하겠다는 예고
2. **2020년 이전 — 과제를 시키려면 학습을 시켜야 했다**
   - fine-tuning이 기본이던 시절. 과제마다 데이터셋과 학습 비용이 필요했던 구조
3. **GPT-3가 바꾼 것 — 입력 텍스트가 곧 과제 지시가 된다**
   - few-shot, in-context learning의 의미. 논문 원문이 말한 "텍스트 상호작용만으로" 부분 인용
4. **Chain-of-Thought — 프롬프트가 성능을 좌우한다는 증명**
   - 같은 모델, 같은 질문이라도 예시에 풀이 과정을 넣으면 결과가 달라진다는 것의 의미
5. **공식 문서가 정리한 기법의 체계**
   - Anthropic 문서의 전제 조건(성공 기준·평가 먼저)과 기법 목록. "모든 문제를 프롬프트로 풀지 말라"는 권고까지
6. **프롬프트 엔지니어링의 전제 — 한 턴, 한 과제**
   - 이 단계의 설계 대상은 "문장"이다. 입력 한 번과 출력 한 번 사이를 최적화한다는 전제
7. **마무리 — 전제가 깨질 때 다음 단계가 온다**
   - 여러 턴을 도는 에이전트가 등장하면 무엇이 부족해지는지 질문만 열어 둔다 (02 예고)

## 시리즈 인용 관계

이 단편은 시리즈의 **출발점**이다. "설계 대상이 문장이다"라는 이 편의 결론을 02~04가 비교 기준으로 쓴다. 6번 절에서 "한 턴, 한 과제라는 전제가 깨지면?"이라는 질문을 일부러 열어 두고, 답(멀티 턴 에이전트와 컨텍스트 관리)은 **02 — 컨텍스트 엔지니어링**으로 넘긴다. 논문 2편의 인용은 이 편에서만 하고 뒤 단편은 "01에서 본 것처럼"으로 줄인다.

## 작성 메모

- **"prompt engineering"이라는 용어 자체의 최초 기원은 공식 출처로 확인하지 못했다.** 기법의 기원(논문 2편)만 말하고, 용어가 언제 누구에게서 시작됐는지는 단정하지 않는다.
- 논문 인용은 제목·저자·플랫폼(arXiv)·URL을 본문이나 출처 절에 명시한다.
- 기법 백과사전이 되지 않게 주의한다. 이 글의 각은 "기법 소개"가 아니라 "왜 이게 분야가 됐고, 어떤 전제 위에 서 있나"다. 기법 나열은 5번 절에서 공식 문서 링크로 처리한다.
- fine-tuning 시절 묘사는 Brown et al. 논문이 서론에서 대비하는 수준까지만 쓴다. 그 이상의 역사 서술은 근거가 없으므로 넣지 않는다.
