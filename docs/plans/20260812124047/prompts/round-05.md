## 0) 이번 라운드의 성격

라운드 1~4 총점: 67.0 → 67.15 → 66.45 → 62.05. **네 라운드 연속 제자리거나 하락이다.**

메타 분석([`../_review/02-eval-observability/_meta-analysis.md`](../_review/02-eval-observability/_meta-analysis.md))
으로 원인을 찾았고, 문서가 아니라 **채점 방식**에 있었다.

- 확정 결함 수가 29 → 26 → 33 → 30으로 줄지 않았다.
- 새 결함의 58~75%가 직전 라운드 수정이 만든 것이었다.
- 합격선 85는 C축 결함이 경미 3건 이하일 때만 나오는데, 매 라운드 5~9건이 나왔다.
- 유일하게 크게 오른 축(B, 89 → 97)은 검증 범위를 명시적으로 닫은 축이었다.

**그래서 라운드 5는 척도 v2로 돈다.** 바뀐 것 셋이다.

1. **경미·사소는 감점하지 않는다.** 점수는 구현을 막거나 틀린 결과를 내게 하는 결함만 반영한다.
2. **동결 목록이 생겼다.** 이미 코드로 확정된 것은 다시 감점하지 않는다.
3. **같은 자리를 3회 이상 고친 곳은 감점 대상이 아니다.** 설계 재검토 안건으로만 받는다.

라운드 5의 목표는 점수를 올리는 것이 아니라 **남은 치명·중대 결함이 몇 건인지 정확히 아는
것**이다. 그 수가 곧 구현 착수 가능 여부다.

```
검색 쪽 선택지에 붙은 전제 셋이 실제 코드와 맞는지, 열린 질문 2의 두 줄에 적힌 한계 서술이
정확한지. 선택지가 틀렸으면 그건 감점이다. "왜 하나로 안 정했나"는 감점이 아니다.
```

### 축 D · 실행 가능성 (배점 20, R4: 38)

```
라운드 4가 02a를 새로 만들고 0a·0b·0c로 재편했다. **빈 모듈에서 시작해 02a대로 따라갔을 때
컨텍스트가 뜨는지 처음부터 다시 시뮬레이션하라.** 이것이 이번 라운드 D축의 본체다.

특히:
1. 02a의 "먼저 정할 것"(JobRepository)에서 셋째를 골랐을 때, 남은 요건만으로 실제로 뜨는가.
   없어지는 일곱 항목이 정확한가.
2. `@Import` 최소 집합이 이제 빠짐없는가. 라운드 4에서 `CohereReRankingServiceImpl`과
   `IntentClassificationServiceImpl`을 추가했다. 또 빠진 평범한 스테레오타입 빈이 있는지
   `api/chatbot` 아래 `@Service`/`@Component`를 전수로 세어 대조하라.
3. 0a의 새 명령(`:api-chatbot:jar` SKIPPED 여부)이 정말 결정적인가. **빌드를 돌리지 말고**
   Gradle 공식 문서로 판단하라.
4. 완료 기준 14개의 `[앞]`·[뒤]` 분할이 실제로 두 작업을 독립 판정 가능하게 만드는가.
   `[앞]` 8개만으로 앞 작업이 완결되는지, `[뒤]` 6개가 앞 작업 산출물에 의존하는지.
5. 0b(JobRepository 결정)가 진행 순서에 들어갔는데, 그 결정에 필요한 정보가 0b 시점에
   다 있는가.

보지 말 것: 동결 목록의 D축 항목 전부, `batch/eval` 요건의 항목 수 논쟁.

**열린 질문 3(JobRepository 위치)은 감점 대상이 아니다.** 다만 위 1번 시뮬레이션은 여전히
해야 한다 — 세 선택지 각각을 골랐을 때 실제로 뜨는지가 이 축의 본체이고, **고르는 데 필요한
정보가 02a에 다 있는지**가 판정 대상이다. 정보가 빠져 있으면 감점이다.
```

### 축 E · 문서 품질 (배점 10, R4: 52)

```
**분량은 이번 라운드부터 채점 대상이 아니다.** 네 라운드 연속 압축에 실패했고 원인이 매번
같았다 — 결함을 고치는 서술이 압축분보다 컸다. 분량을 목표로 삼는 것을 그만둔다.

대신 둘만 본다.
1. **같은 사실이 두 번 이상 나오는가.** 라운드 4가 "조용한 실패"와 `status` 전수 확인 중복을
   정리했다. 남은 중복을 줄 번호로 짚어라. 특히 02와 02a 사이에 같은 서술이 겹치는지.
2. **구조가 탐색 가능한가.** 라운드 4에서 `(a)`~`(e)`가 제목으로 승격됐다. 여전히 제목 없이
   긴 절이 있는지, 없는 절 이름을 가리키는 참조가 또 있는지(세 라운드 연속 재발했다),
   파일명 없는 약식 인용이 직전과 다른 파일을 가리키는지.

**감점은 이 둘이 읽는 사람을 실제로 헤매게 할 때만 한다** — 중복이 서로 모순되거나, 참조가
존재하지 않는 곳을 가리켜 확인이 불가능한 경우다. 그 외 표현·문체 지적은 개선 제안으로 적는다.

보지 말 것: 분량, 볼드 밀도, 상투어(0건 확인됨), 이미 압축한 곳.
```
